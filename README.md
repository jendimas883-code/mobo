# mobo

一个只使用官方 Discord Bot API 的中文群友机器人。mobo 是服务器里的一个活跃成员，会在群聊里自然回应提及和回复，理解近期对话，通过平时聊天被动形成克制而可删除的记忆，并让自己的情绪、关系、偏好和经历缓慢变化。

它不是 selfbot，不使用个人 Discord Token。项目遵循 GPL-3.0-or-later，衍生归属与修改说明见 [NOTICE](NOTICE)。

## mobo 的特点

- **像在聊天，不像在点菜单**：提及 mobo、回复它，或在连续对话窗口内接着说即可公开聊天；生成前会显示“正在输入”。
- **能听完再回答**：同一用户短时间连续发送的消息会经过 debounce 合并到上下文；新消息会取消旧思考，旧答案不会迟到后插进频道。
- **有自己的状态**：核心人格稳定，临时情绪会回归基线，主题偏好会随公开互动缓慢变化；公开安全的服务器经历让 mobo 有一点连续感，但不会伪造个人经历。
- **理解聊天意图**：用本地规则先识别倾诉、分享、求建议、分析、玩笑、纠正、危机等倾向，不为识别本身增加模型调用，也不永久给用户贴标签。
- **会修正相处方式**：能从明确表达中学习称呼、回复长短、是否使用表情和称呼边界；含糊表达不写入。
- **会记得未完的话题**：对明确的未来时间表达建立有期限的待关心事项，之后在合适的直接对话中自然问候；敏感事项不会在公屏提起。
- **反馈会产生小幅影响**：原始提问者对 mobo 回复添加 👍、👎、❤️ 等反应时，会形成有界反馈，不会被其他围观者随意改写用户画像。
- **动态楼层总结**：只有用户明确要求时才从 Discord 拉取指定范围，不常驻灌入大量频道历史；消息数、实际抓取量、字符量、token、模型调用、并发、用户限流和冷却都有上限。
- **普通聊天一次主模型调用**：不做昂贵的二次“自我审查”，输入输出规范由本地安全引擎处理；超长动态总结可能按配置分块调用工具模型；启用了工具桥的服务器最多进行 3 轮有界模型调用（计入预算、审计与冷却）。

## 对话流程

```text
Discord 消息
  ├─ 提及 / 回复 / 连续对话 → 必定进入回复流程
  └─ 普通消息 → 仅在已监听频道内评估是否主动参与
         ↓
本地输入安全 → 连续消息合并与取消旧思考 → 相关记忆检索
         ↓
人格 + 情绪 + 关系 + 用户边界 + 近期频道上下文 + 当前意图
         ↓
一次模型回复 → 本地输出安全 → 公屏发送 → 克制地更新记忆与状态
```

群聊回复始终公开。`/忘记我`、`/隐私`、管理命令以及管理台内容只对调用者显示。公开回答的模型上下文不会加载完整的个人记忆、昵称、喜恶或称呼边界，只保留不可逆的回复长短与反馈计数信号以及同服高置信度的事实/偏好记忆；完整的个人记忆只会在私信等私密范围中按需加载。

## 中文命令

### 普通用户

| 命令 | 用途 |
|---|---|
| `/帮助` | 私密查看自己可使用的命令 |
| `/忘记我` | 二次确认后删除自己在 mobo 中的全部个人数据 |
| `/隐私` | 查看数据保存与隔离规则 |

没有单条”忘记”命令；`/忘记我` 按用户 ID 跨所有服务器和私信范围一次性物理删除。平时直接聊天就行，mobo 会通过对话被动记住该记住的。

### Discord 管理员

| 命令 | 用途 |
|---|---|
| `/状态` | 私密查看连接、模型、情绪和隐私摘要 |
| `/管理台` | 私密返回管理台地址，仍需强密码登录 |
| `/清空频道` | 清空当前频道的已保存上下文和摘要 |
| `/人设 提示词` | 设置服务器级人设覆盖；输入“默认”恢复全局人设 |
| `/频道设置` | 配置某频道是否监听、是否允许主动发言 |
| `/主动发言` | 控制全局主动发言总开关 |
| `/重载配置` | 重新读取配置并刷新状态 |

管理命令有两层限制：Discord 的管理员默认权限负责命令列表可见性，mobo 的 Discord ID 白名单负责实际执行授权。管理员先用网页密码登录，在“安全与权限”添加自己的 Discord ID；非白名单用户即使拥有服务器 Administrator 权限也会被后端拒绝。若白名单用户没有服务器 Administrator 权限，还需由服务器所有者在 Discord 的 Integrations 中授予对应命令权限。

成员回复 mobo 的消息时，可以在内容中写入真实、完整的 `@Discord用户ID`，让 mobo 的公开回复提醒同一服务器中的该成员。每次最多解析 3 人；机器人账号、当前发言者、其他服务器用户、身份组和 `@everyone` 都不会被代为提醒。普通提及 mobo、但没有回复它的消息不会触发代提醒。

## 动态频道总结

在已经开启监听的频道中，可以：

- `@mobo 总结最近 50 楼`
- `@mobo 详细总结最近 80 条消息`
- 回复某条消息并说 `@mobo 从这里总结到现在`
- 加入“简要”“详细”“时间线”或“行动项”选择摘要方式

“楼”按有效的人类文字消息计算，机器人、Webhook、空消息和命令消息不计入。mobo 直接从 Discord 当前可访问的历史读取范围，不要求数据库预先保存这些消息。超出限制会明确拒绝或标注截断，不会无限拉取上下文。

## 记忆与情感状态

- **自动记忆**：只从直接对话里保守提取明确的第一人称自述；按 `guild_id + user_id` 隔离，有置信度、相关词索引、过期时间和每服务器每人数量上限。同服高置信度的事实和偏好记忆会在公聊中自然使用。
- **按需检索**：回复时只取和当前话题最相关的少量记忆，不把整库塞进提示词。
- **用户画像**：全局保存明确纠正过的称呼、表达风格和边界；不保存模型推测出的敏感身份。
- **关系**：熟悉度、信任、温暖和疲劳按服务器隔离，更新和衰减都有边界。
- **mobo 状态**：心情会随互动轻微变化并回归基线；主题偏好和公开经历可由管理员锁定或调整。
- **删除权**：`/忘记我` 会先阻止该用户的新消息进入，取消并等待已接纳的生成与总结任务，再用单一事务删除消息、记忆、关系、画像、待关心事项、反馈、安全元数据、用量统计、管理员权限和来源经历，防止旧任务在删除后写回。
- **总结最小留存**：动态总结结果会公开发到 Discord，但不复制进 SQLite，因为一份摘要可能同时来源于多位用户，无法诚实地归属给单个用户。

Discord 已经发送出去的消息不受 mobo 数据库控制。数据库升级前的备份也可能保留旧数据，管理员应按自己的备份保留政策删除过期备份。

## 安全与隐私

- 输入和输出都经过本地 NFKC 标准化与规则检查，拦截时不调用额外审查模型；数据库规则临时读取失败时沿用最后一次有效规则，首次加载失败则安全拒绝。
- 管理台可配置输入词、输出词、规范提示词，以及 `包含 / 整词 / 正则` 和 `阻断 / 脱敏 / 仅记录` 规则。
- 内置检测 Discord Token、Webhook、常见 API Key、私钥和密码样式；安全事件只保存 hash 与元数据，不保存命中原文。
- 频道历史、用户名、摘要、记忆、经历和用户画像在模型上下文中一律标记为不可信数据，不能覆盖系统规则。
- mobo 不自动 @ 用户或角色，避免模型输出制造骚扰通知。
- 主动发言默认关闭，并同时受全局开关、频道开关、静默时段、冷却、每日上限、关系、偏好和 token 软预算约束。

## 可视化管理台

登录后可管理：

- **总览**：Discord 状态、数据库统计、情绪、偏好与审计摘要。
- **全部配置**：人格、记忆、关系、情绪、连续对话、动态总结、主动发言、限流、保留期与 token 预算。
- **模型中心**：统一填写一个 OpenAI 兼容端点和 API Key，拉取模型、真实测试、启用聊天/深度/后台模型，并调整生成参数。
- **性格与行为**：通过服务器、频道和授权模式下拉框配置频道；服务器人设默认不存在，只会在手动添加后覆盖全局人设，并可物理删除。
- **记忆库**：按服务器和用户查看、筛选和物理删除长期记忆。
- **安全与权限**：Discord 管理员 ID、违禁/脱敏规则、安全事件、管理员密码与会话。
- **审计记录**：记录重要的管理、权限、配置和删除操作。

管理台左下角显示 Discord 当前 Bot 用户名与头像。点击身份卡会重新从 Discord 拉取 Bot 身份，并逐个清除已安装服务器中的独立昵称与服务器头像，使它们重新继承开发者平台“机器人”页面中的全局身份；权限不足的服务器会单独报告，不影响其他服务器。

为了让管理台本身能够安全启动，以下启动级配置仍必须来自 Zeabur Variables 或本地 `.env`，网页只显示状态而不回显秘密：`DISCORD_TOKEN`、首次 `ADMIN_PASSWORD`、`SESSION_SECRET`、`CONFIG_ENCRYPTION_KEY`、`DB_PATH`、监听地址和域名。模型 API Key 可在网页填写，使用 `CONFIG_ENCRYPTION_KEY` 加密后保存。

## 模型接口

mobo 只保留一个 OpenAI 兼容接口。端点需要实现 `/models` 与 `/chat/completions`；官方 OpenAI、提供 OpenAI 兼容 API 的聚合服务或本地服务都通过同一组“端点 + API Key”配置。无鉴权接口可以清空 API Key。

聊天模型、深度模型和后台整理模型可以分别选择，后两者未单独配置时回退到聊天模型。拉取与“仅测试”不会改动运行配置；“测试并启用”成功后才会原子保存连接和模型。更换端点或密钥时必须先启用聊天模型，并会清空旧连接下的深度与后台模型，避免混用。旧版 OpenRouter 配置会自动迁入兼容端点；旧版 Anthropic 原生接口无法安全转换，需要在模型中心重新配置兼容端点。

## Discord 应用准备

1. 打开 [Discord Developer Portal](https://discord.com/developers/applications)，创建 Application 并添加 Bot。
2. 在 **Bot → Privileged Gateway Intents** 打开 **Message Content Intent**。
3. 在 **OAuth2 → URL Generator** 选择 `bot` 与 `applications.commands`。
4. 至少授予 View Channels、Send Messages、Read Message History、Use Application Commands。
5. 使用邀请地址添加机器人，把 **Bot 页面生成的官方 Token** 放进 `DISCORD_TOKEN`。不要使用“客户端密钥”，也不要使用个人账号 Token。

全局 Slash Command 初次同步后可能需要一点时间出现在客户端。

## 本地运行

要求 Python 3.12+。

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m app.tools generate-secrets
```

复制 `.env.example` 为 `.env`，填写：

```dotenv
DISCORD_TOKEN=官方机器人Token
ADMIN_USERNAME=admin
ADMIN_PASSWORD=至少16位且含大小写字母数字特殊字符
SESSION_SECRET=生成值
CONFIG_ENCRYPTION_KEY=生成值
DB_PATH=data/mobo.db
HOST=0.0.0.0
PORT=8080
PUBLIC_BASE_URL=http://localhost:8080
COOKIE_SECURE=false
ALLOWED_HOSTS=localhost,127.0.0.1
```

启动并访问 `http://localhost:8080`：

```bash
python -m app.main
```

首次成功初始化后，管理密码以 Argon2id 哈希保存。环境中的 `ADMIN_PASSWORD` 以后不再覆盖数据库密码。

## Zeabur 部署

完整操作见 [docs/ZEABUR.md](docs/ZEABUR.md)。关键约束：

1. 从 GitHub 仓库部署根目录 `Dockerfile`；`docker-compose.yml` 只供本地使用。
2. **第一次正式启动前**创建 Volume 并挂载到 `/data`。
3. 设置 `DB_PATH=/data/mobo.db`，副本数保持 **1**。进程锁会拒绝同目录第二实例。
4. 设置 `DISCORD_TOKEN`、`ADMIN_USERNAME`、`ADMIN_PASSWORD`、`SESSION_SECRET`、`CONFIG_ENCRYPTION_KEY`、`COOKIE_SECURE=true`、`PUBLIC_BASE_URL`、`ALLOWED_HOSTS` 和 `LOG_LEVEL=INFO`。`PORT` 由 Zeabur 注入。
5. 添加 HTTPS 域名，把健康检查路径设为 `/healthz`。
6. 首次登录后依次添加 Discord 管理员 ID，在模型中心填写兼容端点与密钥并测试启用，随后授权监听频道；主动发言按需最后开启。

更新前暂停服务并备份 `/data`。必须长期保存 `CONFIG_ENCRYPTION_KEY`；换掉它会导致数据库中已有模型密钥无法解密。

## 运维边界

- 当前架构是单服务、单进程、单 SQLite 写入者；需要多副本时必须先迁移 PostgreSQL，并增加共享限流、任务去重和 Gateway ownership。
- Discord 登录失败时管理台会继续运行，便于查看状态和修正模型/权限配置；修正 Bot Token 等启动变量后需要重新部署。
- Zeabur 挂载 Volume 的服务更新会有短暂停机，这是单实例 SQLite 的预期取舍。
- 不要把 `.env`、Token、API Key、数据库、迁移备份或实例锁文件提交到 Git。
- 数据库会在待执行 schema 升级前创建同目录备份；确认升级稳定后，应按隐私与空间策略处理旧备份。
